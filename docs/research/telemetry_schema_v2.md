**Document Version:** 1.0  
**Phase:** 1 (Truth & Baseline) — WP-02 / WP-02b  
**Status:** IMPLEMENTED & VERIFIED

## 1. Overview and Objectives

Telemetry Schema v2 provides truthful, provenance-attributed observability across PhantomCache. Every data point emitted by the gateway explicitly declares its provenance source, window, and collection method, eliminating simulated or misleading figures from the production serving path.

### 1.1 Provenance Hierarchy (§6.4.1)

Every metric field is structured with provenance metadata:

| Provenance Class | Definition |
|---|---|
| `measured` | Direct counter or clock reading at a specific collection point. |
| `derived` | Computed from measured values by a deterministic formula over a specified window. |
| `simulated` | Generated by synthetic models or constant demo loops (**forbidden in `live` mode**). |
| `inferred` | State deduced from indirect evidence (e.g. peer suspect state inferred from connection failures). |
| `unavailable` | Data that cannot be provided on the current platform, state, or configuration. |

### 1.2 Unavailable Value Representation Rule

Whenever a metric or capability is unavailable:
- It is represented as an object: `{"src": "unavailable", "reason": "<code>"}` (with optional `"unit"` for numeric types).
- **CRITICAL:** It contains **no `v` field** (never `0`, `null`, `false`, or `""` standing in for a missing value).
- Contract tests recursively walk the JSON structure in `live` mode to assert that **no field carries `src: "simulated"`**.

## 2. Field Catalog (Schema 2)

### 2.1 Root Structure

| Field | Type | Provenance | Description |
|---|---|---|---|
| `schema` | integer | `measured` (config) | Constant `2`. |
| `mode` | string | `measured` (config) | `"live"` unless `PHANTOM_SIMULATION=true` is set, which yields `"simulation"`. |
| `as_of_ms` | integer (ms epoch) | `measured` | Wall-clock timestamp when the payload was built (`DiagnosticBuffer::now_ms()`). |
| `uptime_ms` | integer (ms) or unavailable object | `measured` | Monotonic elapsed time since process startup. `{"src":"unavailable","reason":"telemetry_disabled","unit":"ms"}` when no telemetry collector exists (never a measured 0). |
| `capabilities` | object | `derived` | Architectural runtime capabilities (cluster, controller, origin_metrics). |
| `metrics` | object | `measured`/`derived` | Core serving, cache, latency, and origin metrics. |
| `hot_keys` | object | `unavailable` | Marked `{"src": "unavailable", "reason": "not_implemented"}` (deferred to PIE/lab). |
| `nodes` | array | `inferred` (cluster) | Cluster node topology. Empty `[]` for a standalone gateway in live mode (BD-03): the placeholder nodes main.rs creates are not reported. With a router each node has `state_src: "inferred"`. Nodes are listed with `state_src: "simulated"` only when `mode` is `simulation`. |

### 2.2 Capabilities Catalog

```json
"capabilities": {
  "cluster": "disabled",       // "experimental" if router configured; else "disabled"
  "controller": "none",        // "active" if PIE controller enabled; "none" in Phase 1
  "origin_metrics": "available" // "available" if origin_url configured; else "unavailable"
}
```

### 2.3 Metrics Catalog

| Field | Unit | Provenance | Collection Point / Formula | Window |
|---|---|---|---|---|
| `requests_total` | count | `measured` | Gateway GET request counter (`server.rs`) | Cumulative |
| `cache_hits` | count | `measured` | `CacheCounters::cache_hits` atomic | Cumulative |
| `cache_misses` | count | `measured` | `CacheCounters::cache_misses` atomic | Cumulative |
| `coalesced_waiters` | count | `measured` | `CacheCounters::coalesced_waiters` atomic | Cumulative |
| `evictions_total` | count | `measured` | `CacheCounters::evictions_total` atomic | Cumulative |
| `capacity_rejections` | count | `measured` | `CacheCounters::capacity_rejections` atomic | Cumulative |
| `hit_ratio_cumulative` | ratio | `derived` | `hits / (hits + misses)`. Unavailable when no cache (`cache_unavailable`), when `requests_total` is 0 (`no_requests`), or when requests exist but none was a cache lookup (`no_cache_lookups`). Never 1.0 as a default (BD-02). | Cumulative |
| `hit_ratio_10s` | ratio | `derived` | $\Delta \text{hits} / (\Delta \text{hits} + \Delta \text{misses})$ across 10 s sliding window | Sliding 10 s |
| `hit_ratio_1s` | ratio | `derived` | $\Delta \text{hits} / (\Delta \text{hits} + \Delta \text{misses})$ across 1 s sliding window | Sliding 1 s |
| `throughput_req_s_10s` | req/s | `derived` | $\Delta \text{requests} / \Delta t$ across 10 s window | Sliding 10 s |
| `throughput_req_s_1s` | req/s | `derived` | $\Delta \text{requests} / \Delta t$ across 1 s window | Sliding 1 s |
| `latency_ms` | ms | `measured` | Tail percentiles (`p50`, `p90`, `p95`, `p99`, `samples`) over last $\le 10,000$ GET observations | Count ring |
| `bytes_resident` | bytes | `unavailable` | `{"src": "unavailable", "reason": "not_implemented"}` (until Step S9) | Instant |
| `byte_budget` | bytes | `unavailable` | `{"src": "unavailable", "reason": "not_implemented"}` (until Step S9) | Instant |
| `origin` | object | `measured`/`derived` | Origin fetch observability via `OriginMetrics` | Mixed |
| `process.rss_bytes` | bytes | `measured`/`unavailable` | `/proc/self/statm` on Linux; `unsupported_platform` on Windows | Instant |

## 3. Endpoints and Ingress Protocols

### 3.1 HTTP GET `/api/v1/metrics`
- Direct snapshot polling endpoint.
- Returns `Content-Type: application/json`.
- Enforces JWT role `Observer` if `require_auth_for_control` is active.
- Emits Schema v2 JSON payload.

### 3.2 SSE GET `/api/events`
- Server-Sent Events stream emitting at 10 Hz (100 ms interval).
- **Query Parameter `schema=2`:**
  - Request: `GET /api/events?schema=2`
  - Output: SSE events where `data:` contains Schema v2 JSON.
- **Default (no parameter, v1 compatibility):**
  - Request: `GET /api/events`
  - Output: Retains legacy v1 schema structure for UI / test backward compatibility.
  - **Corrections applied to v1:**
    - `p95_latency_ms`: Emits real measured p95 from `TelemetryCollector::calculate_percentiles_v2()`.
    - `DELETE` operations no longer pollute latency percentiles or decrease the cache hit ratio.

## 4. Serving Path Guardrails (§6.4.5)

To guarantee zero regression on the cache hit path:
1. **Zero New Allocation or Locking on Hit Path:**
   - Canonical key FNV-1a 64-bit hash (`fnv1a_64`) is computed outside all shard mutexes.
   - Observation recording (`RawObservation::new_get`) performs no dynamic heap allocations.
2. **Exclusion of DELETE from Hit Path Metrics:**
   - DELETE records `ObservationKind::Delete`.
   - `calculate_percentiles()` and `calculate_p95()` skip `ObservationKind::Delete`, preventing synthetic zero-latency entries from corrupting tail latency estimates.
   - Hit ratios derive strictly from atomic `CacheCounters` (`cache_hits` and `cache_misses`).

## 5. D-0 backend honesty corrections (2026-10-29)

Owner-authorized corrections; tests in `tests/integration/telemetry_honesty_tests.rs`.

### 5.1 Unavailable instead of fabricated zeros (BD-01)

When `state.cache` is absent, every counter drawn from `CacheCounters` is `{"src":"unavailable","reason":"cache_unavailable","unit":"count"}` with no `v`: `requests_total`, `cache_hits`, `cache_misses`, `coalesced_waiters`, `evictions_total`, `capacity_rejections`, `stale_served_total`, `stale_cap_violations`, and `revalidations.{started,ok,not_modified,error,in_flight}`. With a cache they are `measured` as before (a real 0 stays `v: 0`).

### 5.2 Defaults that looked like measurements (BD-02)

- `hit_ratio_cumulative`: see the catalog row above. `derived` only when hits+misses > 0.
- `uptime_ms`: see the root table.

### 5.3 Provenance key walker (BD-03)

In `live` mode no key named `src` **or ending in `_src`** (for example `nodes[].state_src`) may have the value `simulated`. The contract test walks both. `nodes` is `[]` for a standalone gateway.

### 5.4 Schema 1 `/api/events` (S-7, deprecated, shape frozen)

Field names and types are unchanged (approval A-3). Documented corrections, applied when `PHANTOM_SIMULATION` is not enabled:

| v1 field | Live-mode value | Before |
|---|---|---|
| `hot_keys` | `[]` | hard-coded `/availability/hotel/123` entry |
| `nodes` | `[]` | startup placeholder nodes (28.4 % CPU, 536870912 bytes) |
| `metrics.backend_load_ratio` | `null` | startup snapshot value |
| `metrics.avoided_compute_dollars` | `null` | startup snapshot value |
| `metrics.throughput_req_sec` | `rate_sampler.throughput_1s()` (derived), `null` without telemetry | startup placeholder 12000 |
| `metrics.p50/p90/p95/p99_latency_ms` | measured percentiles; `null` while the ring has no samples or no cache | placeholder 10/12/15 ms |
| `metrics.hit_ratio` | derived; `null` until the first lookup | 1.0 |
| `timestamp_ms` | wall clock at emission | startup time |

Additive top-level object `v1_provenance`:

```json
"v1_provenance": {
  "mode": "live",
  "note": "...",
  "fields": { "hot_keys": "unavailable", "nodes": "unavailable", "metrics.throughput_req_sec": "derived",
              "metrics.p95_latency_ms": "measured", "metrics.hit_ratio": "derived",
              "metrics.cache_hits": "measured", "metrics.backend_load_ratio": "unavailable", "...": "..." }
}
```

`fields` keys are dotted paths into the payload; values are `measured`, `derived`, `simulated` or `unavailable`. With `PHANTOM_SIMULATION=true` the legacy synthetic values are emitted unchanged and marked `simulated`. Counters stay numeric `0` without a cache (frozen type) with provenance `unavailable`. Clients that do not know `v1_provenance` may ignore it. Removal date follows the v1 sunset (31 Dec 2026).

### 5.5 `truthful` on `/api/v1/intelligence/status`

The literal `true` is replaced by a computed value: `!PHANTOM_SIMULATION`, with `truthful_basis` describing what it does and does not claim. It does not assert decision quality.

### 5.6 Known remaining items

- `main.rs` still builds the three placeholder nodes and the synthetic `initial_snap`; they are no longer emitted in live mode but remain in memory (not edited here).
- Browser SSE authentication (BD-05) is not implemented: see `docs/design/sse_auth_options.md`.
- The UI Overview shows `uptime_ms` through `Number.isFinite`, so an unavailable uptime renders "unknown" but still next to a measured badge (UI not edited).
