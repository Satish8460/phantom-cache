## 1. Goal, scope, non-goals, and what Phase 1 provides to Phantom Intelligence
**Goal.** Make the single-node serving path trustworthy and measurable: (1) everything reported is measured or labeled; (2) known architecture gaps are pinned by *validly reproducing* evidence; (3) reproducible baselines exist with stated noise; (4) correct reference algorithms exist; (5) cache memory is bounded in logical bytes; (6) the pre-existing work is provably preserved.
**Non-goals.** Fixing cluster defects; optimizing the hot path; changing eviction algorithms, TTL semantics, epochs/fencing; any controller or learning; enabling or changing the PIE; end-to-end origin-degradation experiments (need the lab); WP-30…37.
**1.1 PIE posture (unchanged and disabled).** `src/control/pie.rs` stays byte-identical; `main.rs` keeps `pie: None`; Phase 1 does not construct, call, extend or re-label its decision behavior. The UI reports `capabilities.controller = "none"`. The legacy `p4_pie_tests`/`wp2_tests` remain untouched. No synthetic or unverified metric may justify a policy transition (none can occur).
**1.2 Prerequisites Phase 1 establishes for Milestone 5.** The signal inventory below states what exists after Phase 1. "PIE-safe" means: suitable as an input to a *future* PIE under the provenance gate in `phantom_intelligence_phase.md` §1; Phase 1 does not consume any of it.
| Signal | After Phase 1 | PIE-safe |
|---|---|---|
| hits, misses, coalesced waiters, evictions, capacity rejections (cumulative counters) | measured | yes |
| windowed hit ratio, request rate | derived (server-side) | yes |
| GET latency percentiles | measured, **1 ms resolution** (hits <1 ms record as 0); DELETE excluded | tail only, with caveat |
| origin requests, in-flight, errors by class, origin latency | measured (new) | yes |
| logical cache bytes (budget, resident, rejections) | measured (accounted, **not** RSS) | yes, for budgets only |
| process RSS | measured on Linux; unavailable on Windows | no on Windows |
| per-key frequency / hot keys / skew / working set / workload shift | **absent** (Count-Min unused; observations never exposed) | n/a |
| invalidation rate, stale-served counts, freshness metrics | absent until WP-14 | n/a |
| per-miss origin cost | partially derivable from origin latency; not attributed per key | no |
| node health / cluster state | inferred, sticky Suspect; **simulated in standalone** | **no** |
| node CPU/memory, avoided dollars, hot-key list | unavailable (live) / simulated (sim mode only) | **no** |
**1.3 Serving-path and distributed limits that bound safe intelligence** (documented, not fixed): GET is local-only; peer invalidations do not reach the serving cache; reconciliation has no production caller; staleness bound is a fixed 60 s TTL; telemetry uses one global lock; latency resolution 1 ms; eviction is O(shard) scan. These go into the completion report §Limitations.
**1.4 Requirement preserved:** a product-ready MVP needs a real, integrated, auditable intelligence path (M-6); a simulated or hard-coded PIE is insufficient. Phase 1 does not claim any part of it.

## 4. Governing rules (apply to every step)
1. **Preserve first.** No repo file is modified before the S0 snapshot is verified (§6.1).
2. **Change ledger.** Every file AG creates, modifies, or generates is recorded in `phase_1_progress.md` §Ledger with step id, purpose, and `NEW | MODIFIED-PREEXISTING | MODIFIED-PRIOR-PHASE1 | GENERATED-UNTRACKED | GENERATED-IGNORED`. A file changed but absent from the ledger is **UNEXPECTED** and blocks completion. Authorized paths: §9.
3. **Command log.** Every command run and its exit status/summary is appended to the progress log; long outputs are saved under `bench-results/logs/` (untracked) and referenced.
4. **Cargo discipline.** Use `-j 1`. Use `--locked` until S3 intentionally changes `Cargo.lock`; if `--locked` fails on the unchanged tree, **stop** (do not let Cargo rewrite the lockfile). Never run `cargo fmt` (except `--check`), `cargo fix`, `cargo clippy --fix`, `npm audit fix`, or `npm ci` in `ui/`.
5. **No concurrent CPU work during measurement windows.** Authoring may overlap; no builds, tests, or other benchmarks may run while a measurement window is open.
6. **Baseline integrity.** `src/**` must hash-equal the S0 manifest from S0 until the start of S7; S4 verifies and records this before and after measuring (§5.1).
7. **Git.** Read-only commands only (`status`, `diff`, `log`, `ls-files`, `rev-parse`, `archive`, `apply --check`). Never `add`, `commit`, `push`, `stash`, `reset`, `clean`, `checkout/restore`, `rm`, `mv` on tracked content, or `git worktree`/branch operations.
8. **Honesty.** Failed attempts, unfit benchmarks, deviations and surprises are recorded, not smoothed.
9. **Stop conditions belong to the owner.** Every stop condition and gate in this package can be waived, narrowed or reinterpreted **only by the owner, in writing, for the specific instance**. AG never decides that a difference is benign (the only pre-authorized allowance is the documentation whitelist `W` in §6.1 S0.2, which is a rule, not a judgement), never relabels a failure as "expected", never continues past a stop, and records each owner decision (date, wording, scope) in the progress log §3. The "Do not pause" list in §10 covers ordinary implementation choices only, never a stop condition.
10. **No secrets in records.** Logs, manifests, reports, progress entries and screenshots never contain environment-variable values, tokens, keys, passwords or request bodies; record names, paths, line numbers and classes only. Anything secret-like AG encounters is reported as `path:line:class`.

### 6.1 Snapshot and state-capture procedure (S0) — resolves correction B and review findings 1, 5, 6
**Conventions (reproducibility).** Shell: **Git Bash (MSYS2) on Windows**; every command runs from the repository root: `cd /d/Personal/phantom-cache`. Set `export LC_ALL=C MSYS_NO_PATHCONV=1`. Required tools — verify with `command -v` and `--version` first, stop if any is missing: `git`, GNU `tar`, `sha256sum`, `sort`, `join`, `find`, `xargs`, `stat`, `rg`, `cygpath`, `icacls`. All path lists are **NUL-delimited**; all manifest paths are **repo-root-relative, forward slashes, no leading `./`, sorted with `LC_ALL=C sort -z`**. Hashing is `sha256sum -b` (binary; no EOL translation). Copies are made with **`tar`** (byte-exact, no EOL conversion, preserves mtime). **Never** run `env`, `printenv`, `set`, or `git config --list` into a log; no environment variable values are recorded.
**Variables.** `REPO=/d/Personal/phantom-cache`; `SNAP_ROOT=/d/Personal/phantom-cache-snapshots`; `TS=$(date -u +%Y%m%dT%H%M%SZ)`; `SHORT=$(git rev-parse --short=7 HEAD)`; `SNAP="$SNAP_ROOT/phase1-$TS-$SHORT"`.
**Destination (A-1).** Outside the repo (cannot alter `git status`); the path must not contain a cloud-sync component (`OneDrive`, `Dropbox`, `Google Drive`, `iCloud`) — check with `case`, stop if it does. Create with `mkdir -p "$SNAP_ROOT"; mkdir "$SNAP"` (the second command **fails if the directory exists**; never reuse or overwrite), then `mkdir "$SNAP"/{meta,tree,verify,tools,ignored_relevant}`. **Restrict access (owner-only):** `icacls "$(cygpath -w "$SNAP")" /inheritance:r /grant:r "${USERNAME}:(OI)(CI)F"` and record the `icacls` output; this changes the ACL of the new directory only. If A-1 is not approved, or the owner names another path, AG stops (it never chooses a path itself).

**S0.1 Read-only pre-checks (all must pass; any failure ⇒ STOP and report).**
```
git rev-parse HEAD; git branch --show-current; git stash list | wc -l; git diff --cached --name-only | wc -l
df -k "$SNAP_ROOT" 2>/dev/null || df -k /d      # free space >= 5 GB (5242880 KB)
( git ls-files -z; git ls-files -o --exclude-standard -z ) | sort -z -u > "$SNAP/meta/all_paths.z"
tr '\0' '\n' < "$SNAP/meta/all_paths.z" | sort -f | uniq -di          # case-colliding names: must print nothing
tr '\0' '\n' < "$SNAP/meta/all_paths.z" | awk 'length($0)>240'         # over-long paths: must print nothing
tr '\0' '\n' < "$SNAP/meta/all_paths.z" | LC_ALL=C grep -nP '[^\x00-\x7F]' || true   # non-ASCII names: list (recorded; not fatal if hashes verify)
while IFS= read -r -d '' p; do [ -L "$p" ] && echo "SYMLINK: $p"; done < "$SNAP/meta/all_paths.z"   # must print nothing
powershell.exe -NoProfile -Command "Get-ChildItem -LiteralPath '$(cygpath -w "$REPO")' -Recurse -Force -ErrorAction SilentlyContinue | Where-Object { \$_.Attributes -band [IO.FileAttributes]::ReparsePoint -and \$_.FullName -notmatch '\\\\(target|node_modules|\.git)\\\\' } | Select-Object -First 20 -ExpandProperty FullName"   # must print nothing
```
**Symlinks and reparse points:** none are expected. Any hit ⇒ STOP (AG does not follow, copy, or reinterpret links). **Permissions:** NTFS has no POSIX modes; the capture records `git ls-files -s` (tracked modes) and `stat -c '%a %s %Y %n'` per file into `meta/file_stats.txt` for information only; restore does not depend on permissions.

**S0.2 Expected-state comparison and who decides.** Compare the observed state with §2 (HEAD, branch, stash 0, staged 0, the 16 modified + 16 untracked entries, the top-level ignored set). **Allowed without a decision:** differences **confined to the documentation whitelist `W` = `docs/research/**`, `CLAUDE.md`, `docs/handoff/05_OPEN_RISKS_AND_NEXT_STEPS.md`** (documentation by the research lead); AG records each such difference (path + sha256) in the progress log and proceeds. **Everything else** — a different HEAD/branch, non-zero stash or staged count, any added/removed/modified path outside `W`, a different ignored set — ⇒ **STOP and report to the owner with evidence**. **Only the owner** decides, in writing and for that specific difference, whether to proceed, update §2, or abort. AG never classifies a difference as "benign" outside `W` and never waives a stop condition (§4 rule 9).

**S0.3 Secret screening (before any copy; nothing is copied until it completes).**
- Candidate files = every path in `all_paths.z` plus the ignored items to be considered (S0.5) plus the text of `git diff HEAD --binary`.
- Patterns (PCRE, `rg -P`): private-key headers `-----BEGIN [A-Z ]*PRIVATE KEY-----`; JWT-shaped `eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}`; assignments `(?i)(secret|token|passw(or)?d|api[_-]?key|authorization|bearer)["']?\s*[:=]\s*["']?[A-Za-z0-9+/_\-=.]{12,}`; cloud/VCS tokens `AKIA[0-9A-Z]{16}`, `gh[pousr]_[A-Za-z0-9]{30,}`, `github_pat_[A-Za-z0-9_]{20,}`, `xox[baprs]-[A-Za-z0-9-]{10,}`; credentials in URLs `://[^/\s:@]+:[^/\s@]+@`; **filename classes** `*.pem *.key *.pfx *.p12 *.jks *.keystore .env .env.* id_rsa* id_ed25519*`.
- Output is **location only**: run one pattern at a time and keep `path:line:class` — e.g. `rg -n --no-heading -I -P "<pattern>" -- <files> | sed -E 's/^([^:]+:[0-9]+):.*/\1/' | sed "s/$/:<class>/"` — so matched text is never written. Result: `meta/secret_scan.tsv` (path, line, class).
- **Handling (default; no waiting required):** a file with ≥1 hit is **FLAGGED**. FLAGGED files are **not copied raw**. (i) Text files get a **redacted copy** at the same relative path in `tree/` where every matching line is replaced by `[REDACTED:<class>:line-<n>:<byte-length>]`; (ii) binary files and files in a filename class are **EXCLUDED** (no copy); (iii) for both, record original `path, size, sha256` in `meta/secret_handling.tsv` with handling `REDACTED|EXCLUDED` and class. All other files are `COPIED`.
- **Raw copy of a FLAGGED/EXCLUDED file or an ignored log needs the owner's decision (A-14).** AG's belief that a hit is a false positive is not a decision. The progress log and manifest record paths, line numbers, classes and handling — **never values**. Consequence stated in the manifest: FLAGGED/EXCLUDED files remain preserved only in the untouched working tree unless the owner approves a raw copy; S0 does not modify them.

**S0.4 Metadata with filtering.** `git config --local -l` is **never stored raw**. Produce `meta/git_config_filtered.txt` from an allow-list: `core.*` except `core.sshcommand`/`core.askpass`; `branch.*`; `remote.*.url` with credentials stripped (`sed -E 's#(://)[^/@]*@#\1[REDACTED]@#'`); `user.*` is omitted. Any key whose name matches `(?i)(token|passw|secret|credential|extraheader|auth|key)` is dropped and only its **name** is appended to `meta/git_config_removed_keys.txt`. Separately record `git config core.autocrlf`, `git --version`, `tar --version | head -1`, `sha256sum --version | head -1`. Also store `git rev-parse HEAD`, branch, `git stash list`, `git diff --cached --name-status`, `git diff --name-status`, and `git status --porcelain=v2 --branch --ignored` (paths only).

**S0.5 Ignored items.** Inventory every ignored top-level item and every file under `ui/dist/` (path, size, mtime, sha256, line count, scan result). `target/` and `ui/node_modules/` are inventoried only (directory size, newest mtime). **Ignored logs `api.log`, `build.log`, `ui/ui.log` are not copied** (regenerable, may contain request data); inventory + sha256 + scan result only, unless the owner approves a copy (A-14). `ui/dist/**` is copied to `ignored_relevant/ui_dist/` only if its scan has zero hits, otherwise inventory-only. Every non-copied or redacted artifact is listed in the manifest with reason.

**S0.6 Capture.**
```
# copy list = all_paths.z minus EXCLUDED paths (from secret_handling.tsv)
LC_ALL=C sort -z -u "$SNAP/meta/copy_list.z" -o "$SNAP/meta/copy_list.z"
tar -cf - --null -T "$SNAP/meta/copy_list_unflagged.z" | ( cd "$SNAP/tree" && tar -xpf - )     # COPIED files, byte-exact
# for each REDACTED path: write the redacted text to "$SNAP/tree/<path>" (mkdir -p its directory first)
xargs -0 sha256sum -b < "$SNAP/meta/all_paths.z" > "$SNAP/meta/original_manifest.sha256"        # hashes of the ORIGINAL working-tree files (repo-root-relative)
( cd "$SNAP/tree" && find . -type f -print0 | sed -z 's#^\./##' | sort -z | xargs -0 sha256sum -b ) > "$SNAP/meta/tree_copy_manifest.sha256"
git diff HEAD --binary > "$SNAP/meta/tracked_changes.patch.tmp"      # kept as tracked_changes.patch only if its secret scan has zero hits; otherwise deleted and noted
git bundle create "$SNAP/head.bundle" HEAD                           # committed history only (read-only on the repo)
```
`tree/` therefore contains the **whole non-ignored tree** (tracked + untracked), byte-exact except REDACTED/EXCLUDED entries — this avoids any dependence on line-ending conversion by `git archive`.

**S0.7 Verification (reproducible; all must pass before any repo write).** AG writes `"$SNAP/tools/verify_snapshot.sh"` implementing exactly the following, records its own sha256, and reruns it in a fresh shell for V3. Working directory for V1/V2 is `$REPO`; paths are looked up in `meta/*.tsv|sha256`; output goes to `"$SNAP/verify/"`.
- **V1 copy integrity.** For every path `p` in `all_paths.z`: look up its handling in `secret_handling.tsv` (default `COPIED`). `COPIED` ⇒ `sha256sum -b "$SNAP/tree/$p"` must equal the hash for `p` in `original_manifest.sha256`. `REDACTED` ⇒ the copy exists, its hash **differs** from the original, and `p` appears in the redaction map. `EXCLUDED` ⇒ no file exists at `tree/$p`. Emit `PASS|FAIL <handling> <path>` per path to `verify/v1_report.txt`; summary counts must satisfy `COPIED+REDACTED+EXCLUDED == |all_paths|` and `tree` file count `== COPIED+REDACTED`.
- **V2 restore simulation.** `mkdir "$SNAP/verify/restore"`; `tar -cf - -C "$SNAP/tree" . | tar -xpf - -C "$SNAP/verify/restore"`; then (a) every `COPIED` path in `restore/` hashes to `original_manifest.sha256`; (b) for each **tracked, unmodified** `COPIED` path: `git hash-object --path="$p" -- "$SNAP/verify/restore/$p"` equals the blob id in `git ls-files -s -- "$p"` (proves unmodified tracked files equal the index, independent of EOL settings); (c) for **tracked, modified** paths: list them (16 expected) with `differs-from-index = yes`; (d) informational: `mkdir verify/head_archive; git archive HEAD | tar -x -C verify/head_archive; (cd verify/head_archive && git apply --check "$SNAP/tracked_changes.patch")` — a failure here caused by EOL normalization is recorded, not fatal, because (a)–(b) pass; if the patch was omitted by the scan, skip (d) and say so.
- **V3 readability from a fresh shell.** `bash -lc 'cd "$SNAP" && find . -path ./verify -prune -o -type f -print0 | sort -z | xargs -0 sha256sum -b > verify/v3_hashes.txt'` and compare with `meta/snapshot_files.sha256` recorded at the end of capture (same command, same ordering); read-test every file (`head -c 1 -- "$f" >/dev/null`); record file count, `du -sb` total, and the `icacls` listing.

**Record.** `docs/research/phase_1_snapshot_manifest.md` (created only after V1–V3 pass): snapshot path and timestamp; tool versions; commands run; counts (`COPIED`/`REDACTED`/`EXCLUDED`, tracked-modified 16, untracked N, ignored-inventoried M); manifest hashes (`original_manifest`, `tree_copy_manifest`, `snapshot_files`, `verify_snapshot.sh`); V1–V3 results; the **excluded/redacted/not-copied artifact list with class and reason (no values)**; the `git_config_removed_keys` names; the ACL record; restore recipe (copy `tree/` over a checkout of HEAD; FLAGGED/EXCLUDED files come from the working tree or an owner-approved raw copy). The snapshot is read-only evidence; AG never modifies it after V3.
**Never done:** `git stash`, `git reset`, `git clean`, `git checkout/restore`, `git add`, `git worktree`, `git init`.

### 6.5 Byte-budget semantics (S9) — resolves correction C
**Nature.** The budget is a **logical cache-accounting budget** — a deterministic estimate of heap bytes *owned by cache entries* — **not** a guarantee about process RSS. RSS is exposed separately (Linux) and will exceed accounted bytes (allocator overhead, in-flight bodies, buffers, telemetry, connection state). The completion report must not claim "memory is bounded to X"; it claims "accounted cache bytes never exceed the configured budget".
**Budget.** `B_total` (A-2 default 268,435,456) is set by `PHANTOM_MAX_CACHE_BYTES` in `main.rs` via `set_byte_budget(total)`; `B_shard = ⌊B_total / num_shards⌋`. `PartitionedCache::new` leaves the budget **unlimited** (`usize::MAX`) so the 242 existing tests keep their behavior. **Fragmentation between shards is accepted** (a hot shard may evict while others have room); a global shared budget was rejected because it would need a cross-shard atomic on every fill/evict/delete; fragmentation is measured in B7 (distribution of per-shard bytes) and documented.
**Accounting formula (per map entry `(key, state)`).**
`state_bytes = key_bytes + resource_bytes + FIXED`, where
- `key_bytes = tenant_id.len() + path.len() + query.map_or(0, len)` (UTF-8 bytes; `capacity()` not used for small strings);
- `resource_bytes = 0` if `entry == None`, else `body.capacity() + content_type.len() + etag.map_or(0, len)` (`capacity()` for the body `Vec` because it is the allocation actually held);
- `FIXED = size_of::<CacheKey>() + size_of::<KeyState>() + 64` (covers hash-map slot padding/control byte, `Arc` control block, allocator headers; **64 is provisional and calibrated by B7**, recorded with the measurement, and may be changed only with a recorded justification).
Placeholders (`entry == None`, in-flight) count `key_bytes + FIXED` (the map really holds them). `in_flight` map clones of the key (`SharedOp`) are **not** separately counted (documented limitation; bounded by waiter/in-flight limits).
**Shared allocations.** The body `Arc<Vec<u8>>` is counted **once per cache entry that owns it**. Transient clones held by waiters/handlers/responses keep memory alive after eviction but are **not** counted (they are bounded by `max_waiters_per_key` and in-flight limits and appear in RSS). If two entries ever shared one `Arc`, both would be charged (conservative over-count); a test asserts the production fill path creates one `Arc` per entry (`(**resource).clone()` shares the body `Arc` with waiters only, not between entries).
**Lifecycle rules (all under the shard mutex, so each is atomic with the map change).**
| Event | Accounting |
|---|---|
| Initiate placeholder insert (`begin_fetch_atomic` miss) | `+ key_bytes + FIXED`; if it would exceed `B_shard`: evict (existing path) up to the cap below; if still not fitting ⇒ reject with `CapacityExceeded` (existing semantics) |
| Fill (`finalize_fetch` Success, fencing/epochs pass) | delta = `new resource_bytes − old resource_bytes (0 for a placeholder)`; if `bytes + delta > B_shard`: evict **other** non-active states (policy order) up to **32 evictions**; if still not fitting or `resource_bytes + key_bytes + FIXED > B_shard` ⇒ **do not store**: the response is still delivered to the initiator and waiters; counters `byte_budget_rejections` / `oversize_rejections` increment; placeholder removed if no active ops |
| Replacement of an existing entry | old resource bytes subtracted, new added (never double-counted) |
| Failed insertion (Error/Uncacheable/stale-fence drop) | no resource bytes added; placeholder removed (existing logic) ⇒ `− (key_bytes + FIXED)` |
| Expiry (TTL passed) | entries stay resident until evicted or replaced (existing behavior): **counted until removed**; eviction already prefers expired entries |
| Invalidation by `delete*` | `entry = None` ⇒ `− resource_bytes`; if no active ops the state is removed ⇒ `− (key_bytes + FIXED)` |
| Epoch-stale (tenant/global) | lazy: `get_resource`/`begin_fetch_atomic` set `entry = None` ⇒ `− resource_bytes`; **entries never touched remain resident and counted** (known limitation: a tenant-wide invalidation does not reclaim memory until touched/evicted; measured and documented, not changed in Phase 1) |
| Eviction | `− state_bytes` of the victim (never a state with active ops/in-flight) |
| `set_capacity_limits` / `set_byte_budget` contraction | evict until both budgets satisfied or nothing evictable; if only non-evictable states remain, `bytes` may exceed `B_shard` (I2′ below) |
**Per-insert eviction cap (32)** bounds work under the lock (current evictors are O(shard) scans); when the cap is hit the fill is not stored and `byte_budget_rejections` increments. This cap is a Phase 1 safety limit, revisited in Milestone 2 (WP-08).
**Concurrency.** `shard.bytes: usize` is a plain field mutated only under the shard mutex; the hit path performs **no** accounting (no atomic, no lock beyond what exists). The reported global value is obtained by locking each shard briefly in the **sampler task at 1 Hz** (not on the SSE tick, not on the request path) and summing.
**Regimes and definitions (resolves review finding 4).** A state is **pinned** if it has active ops or is in `in_flight` (non-evictable); `pinned_bytes = Σ state_bytes(pinned states)`; `excess = max(0, shard.bytes − B_shard)`. A shard is in the **normal regime** when `excess == 0` and in the **excess regime** when `excess > 0`. Only a **contraction** (`set_byte_budget` to a smaller value; `set_capacity_limits` to a smaller entry cap) can move a shard into the excess regime: admissions (placeholder insert, fill) never create excess because they are rejected or not stored if they would not fit, and fills never exceed the budget (§ lifecycle table). The permitted temporary excess exists solely because pinned states cannot be evicted while their operations are in flight.
**Invariants (each has a test).**
- **I1 (accounting equality):** at every quiescent point `shard.bytes == Σ state_bytes(state)` over the shard map (`audit_bytes()`, O(n), diagnostic only), in both regimes.
- **I2 (normal-regime bound):** after every public operation **other than a contraction**, if the shard was in the normal regime before the call, then `shard.bytes ≤ B_shard` after it.
- **I2′ (contraction result):** after a contraction call returns, **either** `shard.bytes ≤ B_shard` (normal regime) **or** `shard.bytes == pinned_bytes > B_shard` (excess regime: every remaining state is pinned; nothing evictable remains).
- **I7 (no growth in excess):** while in the excess regime, no operation increases `shard.bytes`: new placeholder inserts are rejected (`CapacityExceeded`), fills that would add resource bytes are **not stored** (response still delivered; `byte_budget_rejections` increments), hits and deletes never increase bytes. `bytes` is therefore non-increasing until the regime ends.
- **I8 (recovery/convergence):** when a pinned operation completes (`finalize_fetch` success/failure/fence-drop, guard drop, delete), the shard runs a **shrink step** under the same lock: evict evictable states (policy order, never pinned) up to **256** evictions per call until `bytes ≤ B_shard` or nothing evictable remains. After the last pinned state of a shard is released, `bytes ≤ B_shard` holds after at most ⌈N/256⌉ + 1 further mutating operations on that shard (N = number of states when the last pin was released); in the common case (≤ 256 victims) it holds immediately on that release. Re-expansion (`set_byte_budget` larger) performs no eviction.
- **I3 (failure atomicity):** a rejected or failed fill leaves `shard.bytes` equal to its value before the call, except for the placeholder lifecycle terms in the lifecycle table.
- **I4 (semantics unchanged):** fencing/generation/epoch behavior unchanged; the existing SEC-4A and coalescing tests pass untouched.
- **I5 (pins respected):** no pinned state is ever evicted by any path (insert, fill, shrink, contraction).
- **I6 (global equality):** `bytes_resident() == Σ shard.bytes`; the 1 Hz sampler locks one shard at a time, so the global value is a sum of per-shard snapshots taken at slightly different instants (documented; not a consistency claim).
The shrink step is the only addition to completion paths; it lives in `cache.rs` `finalize_fetch`/delete (all placeholder removals pass through them), so `src/core/coalesce.rs` is not modified.
**Tests.** Unit tests for every row of the lifecycle table, plus the **contraction/excess suite**:
- **T-C1** contraction with no in-flight ops ⇒ I2′ first branch (`bytes ≤ B_shard`) immediately; counters consistent.
- **T-C2** contraction while ≥ 3 ops are in flight and the budget is below `pinned_bytes` ⇒ I2′ second branch: `bytes == pinned_bytes > B_shard`, no evictable state remains, no pinned state evicted (I5).
- **T-C3** during the excess regime: a miss on another key ⇒ `CapacityExceeded`, bytes unchanged; a hit is served, bytes unchanged; a fill for an in-flight key that would add bytes ⇒ response delivered, not stored, `byte_budget_rejections` += 1, bytes unchanged (I7).
- **T-C4** recovery: complete the in-flight ops one at a time (success, error, fence-drop, guard-drop variants) ⇒ `bytes` non-increasing at every step; after the last completes `bytes ≤ B_shard` (immediately when ≤ 256 victims; otherwise within the bound in I8); then normal admissions succeed again.
- **T-C5** contraction followed by re-expansion while ops are in flight ⇒ no eviction on expansion, excess disappears, admissions resume.
- **T-C6** concurrent stress: contraction racing with fills, deletes, hits and in-flight completions on one shard (fixed seeds, bounded duration) ⇒ I1 at the end, I7/I5 continuously via debug-build assertions inside the critical section, convergence after quiescence.
- **T-C7** `proptest` over random operation sequences including contraction/expansion and in-flight placeholders, asserting I1, I2/I2′ (by regime), I3, I5, I7 after each step and I8 at quiescence.
Also: integration test filling with 1 MiB bodies under a 32 MiB shard budget ⇒ bounded accounted bytes, counted evictions/rejections; B7 compares accounted vs measured (WSL2 RSS delta / counting allocator) as an **error ratio**, never used to assert the budget; a test asserts the production fill path creates one `Arc` per entry.
**Defaults and approval.** A-2 as above; if A-2 is changed, only the constant changes.
