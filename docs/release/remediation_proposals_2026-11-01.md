## R2. Anonymous control and invalidation access; Host/Origin guard (priority 2)
**Intended behaviour by mode (REPORTED from `docs/user/security.md:25-43,75`, `docs/user/run.md:10`, `src/security/mod.rs:33,44,105-140`, `src/main.rs:412`, `src/config.rs`):**
| Route | Secure mode (`PHANTOM_JWT_SECRET` set; `require_auth_for_control` defaults true) | Development mode (no secret, loopback bind) |
|---|---|---|
| `DELETE /api/v1/cache/*`, `DELETE /api/v1/cache` | Intended and implemented: `cache:invalidate` plus tenant claim (`server.rs:2384-2392`); pinned by role-enforcement and m7 matrix tests | Intended per docs: anonymous, loopback only. Implemented: open, tenant from `x-tenant-id` (`:2396-2403`). Test-pinned: no dedicated anonymous-DELETE test found |
| `POST /api/control` | Operator role (`:1377-1383`); pinned (`security_phase1_tests.rs:372-399`) | Anonymous; pinned by `wp4_tests.rs:156-198` expecting 200 without a token (INFERRED) |
| `GET /api/v1/cache/*` | `cache:read` plus tenant | Anonymous; pinned (`sec01_security_disabled_dev_mode_is_unchanged`) |
| metrics, events, diagnostics, `/api/v1/intelligence/*` | Observer | Anonymous; documented gap |
| `/health*` | Public by design | Public |
Startup refuses a non-loopback bind without a secret (`security/mod.rs:119-124`). Older security documents (`implementation-roadmap.md:32`, `security-demo-matrix.md:90`, `phase-1-specification.md:8`) read as if control is always authenticated; `docs/user/security.md` correctly lists anonymous mutation as a development-mode gap. **Contradiction in code:** `delete_cache_handler` tests `state.security.is_some()` only (`server.rs:2384`) while other handlers also honour `require_auth_for_control`; equal under current wiring, latent otherwise. **The Host/Origin guard exists only on the Lab router** (`lab_api.rs:1060-1094`); the main router (`server.rs:278-306`) has none, so a DNS-rebound page could reach anonymous mutation on a loopback gateway (INFERRED; a rebound same-origin request is not stopped by CORS or by the JSON extractor).
**Demo impact (REPORTED):** `Start-Phantom-Demo.bat` sets no auth variables, so the single-node demo is anonymous; `Start-Phantom-Cluster-Demo.bat` runs `cluster_launcher up --secure` (secret and `PHANTOM_REQUIRE_AUTH=true`), so it is secure; the UI sends DELETE through the console with a token only if pasted; no `/api/control` call exists in `ui/src`.
**Options:** (A, narrow, recommended) Host/Origin guard on the main router for mutating routes only (DELETE, `/api/control`) in anonymous mode, reusing the lab guard (421 for a bad Host, 403 for a foreign Origin; secure mode and `/health` exempt); plus make `delete_cache_handler` honour `require_auth_for_control`. Breaks nothing on loopback; only LAN or device access to an anonymous gateway (relevant to the multi-device Phase 1: that path uses a secret anyway). (B) the same guard on all main routes (also covers anonymous reads). (C, policy change) refuse mutation without a secret unless an opt-in such as `PHANTOM_ALLOW_ANONYMOUS_MUTATION` is set; breaks the single-node Purge button and `wp4_tests`. **Owner decisions needed:** is anonymous loopback mutation a kept feature (A/B) or to be removed (C); narrow or all routes; is a new opt-in variable acceptable; may the single-node demo require a token.
**Test strategy (failing first):** new `tests/integration/m7_anonymous_mutation_tests.rs` (needs a `[[test]]` entry in `Cargo.toml`): anonymous gateway, `DELETE /api/v1/cache/x` with `Host: evil.example` → 421 (today 204); with `Origin: http://evil.example` → 403; `POST /api/control` with a bad Host → 421; a loopback Host and no Origin → success (unchanged); duplicate Host → 421; the same bad Host with a valid JWT in secure mode → unaffected; GET and `/health` → 200 under option A. Regression test that `delete_cache_handler` follows `require_auth_for_control=false`. For option C add 401/403 expectations and update `wp4_tests.rs:156-198`. Documentation: add an explicit DNS-rebinding note to `docs/user/limitations.md` and `security.md`. **Independent review required** (authentication).

## R3. Bypass-path response headers (SEC-2)
`server.rs:1578-1597` sets `X-Cache-Status` / `X-Cache-Source` then copies every origin header except hop-by-hop ones, so an origin can overwrite them and pass `Set-Cookie` and `Access-Control-Allow-Origin` (VERIFIED-IN-CODE; hit, stale, coalesced and miss paths emit fixed headers). Proposal: allow-list (`content-type`, `etag`, `last-modified`, `cache-control`, `content-language`, `content-encoding`), drop `x-cache-*`. Test: mock origin returns `Set-Cookie`, `Access-Control-Allow-Origin: *`, `X-Cache-Status: HIT`; `X-Cache-Bypass` GET must show none of the first two and `X-Cache-Status: BYPASS`; control: content-type passes. Review: security.
