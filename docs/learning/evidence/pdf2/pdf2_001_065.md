## Method

- Script `D:\Temp\pdf2_A.mjs` (outside the repo) used `ui/scripts/cdp-lib.mjs` with its own throwaway Chrome profile. Viewport 1100x1560. For each page N: navigate to `about:blank`, then `file:///D:/Temp/handbook_inspect.pdf#page=N&zoom=page-fit&toolbar=0&navpanes=0`, wait 3 s, `b.shot('pNNN.png')`. Output: `D:\Temp\pdf2_A\p001.png` to `p065.png`.

Font sizes in figures are estimates from rendered pixels; no zoomed crops were taken, so finer overlaps inside figures (a label touching an arrow by a pixel or two) cannot be ruled out.
- Page-number colour appears blue-grey or brown on some pages; this is sub-pixel anti-aliasing of small grey text in the screenshot and is not counted as a defect.

## Recommended fixes (file and location)

The stylesheet and build script that generate the PDF from `docs/learning/PHANTOMCACHE_ENGINEERING_HANDBOOK.md` were not inspected; apply the fixes in whichever file holds the print CSS and the pandoc options.

1. Table of contents (pages 1-5): limit the TOC to chapter and numbered-section level (drop "What you will learn / Key ideas / What you should now understand / Knowledge check / Codebase exploration tasks / Challenge questions"), add page numbers (pandoc `--toc --toc-depth=2` plus a page-number CSS rule such as `target-counter` in the print stylesheet), and put the title on its own cover page. This should cut the TOC from 5 pages to about 2.
2. Orphan table rows (16, 24, 33, 36, 65): CSS cannot set orphans on table rows, so make short tables non-splitting (`table { break-inside: avoid; }` for tables under about 10 rows, via a pandoc Lua filter that adds a class). Affected locations: 1.4 two-design table (page 16), 1.9 use-case table (24), 2.2.1 responsibilities table last row (33), 2.3.3 response vocabulary table (36), 3.3 Tokio feature table (65).
3. Stranded lead-ins (8, 19, 22, 36): add `break-after: avoid` to paragraphs that are bold lead-ins or end with a colon ("How it works.", "What exists, by level.", "What exists (IMPLEMENTED unless noted).", "Steps, as the code does them:"); a Lua filter can wrap such a paragraph and the next block in a `div` with `break-inside: avoid`.
4. Near-blank pages 18, 42, 62: allow judge boxes to break across pages when they exceed about 40 percent of a page (`break-inside: auto` for the judge-box class with `orphans: 4; widows: 4` on its paragraphs), or let the following figure flow without `break-before`. Pages 28 and 57 are expected chapter ends.
5. Figure text (Figures 1.1, 1.3, 3.1 are the worst; 2.1, 2.3, 2.4 are about 6.5 pt): regenerate the SVGs with a larger base font (at least 8 pt at print size) and widen or re-wrap the boxes: Figure 1.1 STALE box text, Figure 1.3 three columns, Figure 3.1 "Verification tools" box (last line touches the border). The SVG sources were not located in this inspection.
6. Mid-word code breaks in narrow table columns (9 pages): widen the "Where" and "Status" columns through explicit column widths in the table CSS, or insert a zero-width break after `::` and `/` with a filter so breaks fall at path separators rather than inside identifiers.
7. Stray rules (11, 18): suppress `hr` at the end of a page or immediately before a heading, or remove the `---` separators that follow judge boxes in the Markdown.
8. "Answers" boxes (27, 56) and inline code in tables: set the box font to the body size (10 pt) and inline code in tables to at least 8 pt.
9. Optional: reduce line length (margins about 2.5 cm or 10.5 pt body) to bring characters per line nearer 90.
