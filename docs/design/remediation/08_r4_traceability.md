## 4. Do not animate (fictional internal events)

These events do not exist in any feed (R4-A section 3 and R4-B M0.1, M6). Drawing them in motion would present a fiction as an event (rule 9; rubric criterion 6 and 10).

1. A token travelling per request, or any per-request path (no request id exists).
2. Followers "joining" a fetch one by one; leader election (a leader is simply the first miss for a key; no join event or timestamp exists).
3. An entry ageing, a TTL or stale-window countdown, an entry moving fresh to expired to reclaimed (no per-entry state; sweeper ticks are not evented).
4. A specific entry being filled, evicted or chosen as a victim; a policy (SIEVE, LRU, S3-FIFO) deciding.
5. A fence decision, a generation bump, an epoch change, a discarded stale write.
6. Invalidation messages flying between nodes, acknowledgements, repair re-delivery, anti-entropy rounds, "reached N of M nodes".
7. A node failing, recovering or being elected primary (NODE_FAILURE is a logical flag; Degraded and Offline are never assigned).
8. A repair backlog filling or draining (no gauge is exposed).
9. Hot keys rising, a skew curve, a burst detected, a workload "emerging".
10. A forecast arriving, a prediction band, a prediction being checked later.
11. Canary buckets (Holdback, Candidate, Control), a guardrail tripping, a rollback, a watchdog (no serving-path caller).
12. The AIMD controller "learning" or "adapting"; a decision with a reason (no decision log).
13. A ticking "origin requests avoided" counter (not a field).
14. 503 shed requests rendered as individual particles (rejections are a counter; followers of a rejected leader also receive 503 and are not counted in `origin_cap_rejections`, INFERENCE from R4-A L2).
15. Any number tweened between frames, any chart line smoothed, any state the code cannot distinguish (rule 9). No motion on stale or reconnecting states.

Allowed motion (summary): a real event or a user action only. Counter deltas may produce a short non-positional emphasis at no faster than the 100 ms frame cadence; real `progress`/`state` events in the Lab; user-pressed "step" in an illustration; opacity-only reduced-motion equivalents.

## 9. Scenario B result page requirements

Source of truth: `docs/demo/scenario_b_interpretation_notice.md` (binding), `summary.json`, DD v2 s10, rubric criterion 10, `ScenarioBResult.jsx` today (FACT: it already has verdicts, labelled paired table, arms table, mechanism, limitations folds).

1. **Order:** source line (REAL with basis and RETAINED stamp), title, the question and what was measured, result at a glance, "Not established" strip at equal weight, binding notice rendered open, then charts, then second-level folds (DD v2 s10.1). The notice is not collapsed and not shortened (Rendered / Raw / Copy unchanged).
2. **Paired comparison:** one column per arm against BASE (`paired_vs_base`), each repetition paired with the BASE repetition of the same index, `n_pairs` printed. Two separate quantities side by side per arm: peak origin concurrency change and client success change, each with its limit stated. Direction captions ("lower is better for origin load"); the zero line labelled "no difference".
3. **Intervals only when supplied:** draw `diff_ci95_bca` and `relative_reduction_ci95_bca` exactly as given. Never compute, widen, narrow or infer an interval. If the success-rate interval is not in the payload, draw no interval and print "interval not supplied" (DD v2 s10.3 notes the data-shape question for the trade-off plane; unresolved).
4. **No tweening, no smoothing:** every value appears at once; no count-up, no animated bars, no curve between points that are not a series, no dual axes. A missing value is a hatched block with its reason, never zero.
5. **No overall score and no overall verdict.** Verdicts stay per arm as recorded (`verdicts.<arm>.outcome`, `reasons`); the UI never combines them. Negative verdicts (`TRADE_OFF_FAILURE`, `NOT_SUPPORTED`) use the same component, size and weight as positive ones.
6. **Binding notice present and quoted verbatim:** not established are adaptive-control merit, origin-p99 benefits, stale-serving effectiveness, served-client latency improvement (FACT: R4-A O45; notice file). The latency panels keep the sentence that percentiles include fast-fail 503s (a lower p50 for AIMD-CAP is largely sheds; V36 context). The AIMD note (effective cap near 12, so AIMD versus BASE is effectively a static cap versus none) stays visible.
7. **Provenance:** per-arm values REAL (loopback, one host, debug build when the build profile says so); paired differences and verdicts DERIVED; unavailable per-phase shed stays a hatched UNAVAILABLE block with its reason.
8. **Cancelled, failed, interrupted runs:** no verdict chip, no "Mechanism failed" for a run that never finished (U-01; backend behaviour owner-reserved; UNVERIFIED by me). Show what happened and what is known.
9. **Tabular equivalent:** every chart has a table twin with identical values and units, reachable without hover, with the same column order. Exact figures in tabular numerals, right-aligned. Charts have `role="img"` with a text alternative.
10. **Motion:** none on measured numbers or charts. A single opacity fade at most for the verdict reveal; reduced motion leaves a complete page.
11. **Wording:** only the six provenance words as labels. "Real (loopback, one host)" is a label plus basis text; prose does not use "measured", "inferred" or "observed" as label substitutes (rule 16).
