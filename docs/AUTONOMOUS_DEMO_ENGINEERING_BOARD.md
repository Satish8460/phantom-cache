## 0. Rules of use (read first, every cycle)

1. Read the whole file before starting a work cycle. Update only the section you own (owners are listed in each heading). **Preserve existing entries; never delete or rewrite another agent's text.** Disagreements and old verdicts stay.
2. Every entry carries: **agent identity, ISO timestamp (machine clock, +05:30), WP or finding ID, snapshot id, action, result, required response from the other agent.**
3. **Snapshot id** = `<HEAD first 8 chars>+<working-tree fingerprint>`. Get it with `node D:\ClaudeTemp\monitor\monitor.mjs fingerprint`. The fingerprint is a hash of path+content of all files under `src tests ui/src ui/test scripts docs Cargo.*` that differ from HEAD or are tracked (build output excluded).
4. Supporting logs, screenshots and traces may live elsewhere, but **every one must be referenced from this board** (path + what it proves).
5. Only AG writes `AG_*` handshake lines. Only Claude writes `CLAUDE_*` lines. Only the coordinator writes `PROGRAMME_STATUS`. The monitor writes **only** inside the MONITOR FEED region (section H2). Neither agent signs off for the other.
6. Concurrent edits: re-read the file immediately before saving; if it changed, merge, do not overwrite. The monitor appends with an optimistic-concurrency check and retries.
7. No finding may disappear. Allowed dispositions: `ACCEPTED`, `PARTIALLY ACCEPTED`, `REJECTED` (with evidence), `DEFERRED` (with impact), `FIXED` (awaiting review), `VERIFIED` (independently reproduced as fixed by Claude), `BLOCKED`. **Silence is not acknowledgement.**
8. Protected: working tree (never reset/clean/stash/checkout/force-push; no stage or commit without explicit owner authorisation), academic workspace, M3 sandbox, research-freeze files, backups, quarantined intelligence modes.
9. **How AG signals a review request:** set the WP's `Status` cell to exactly `READY_FOR_REVIEW`, fill `Files` (backticked repo-relative paths, comma-separated) and `Tests/Evidence`, and add a section-H1 handover entry. The monitor detects it and posts `REVIEW_STATUS: CLAUDE_REVIEW_REQUIRED` in the feed with a review packet.
10. **WP table column order is machine-read:** `WP | Findings | Objective | Owner | Status | Files | Tests/Evidence | Reviewer | Acceptance`. Do not reorder columns or put a pipe character inside a cell.
11. **AG-inactivity fallback (D-012):** if AG does nothing for 30 minutes after a handover to AG, Claude takes the phase, fixes and reviews, and marks its own changes as not independently reviewed.
12. **Live evidence rule (D-013):** every review includes an end-to-end live run with screenshot proof referenced on this board.
